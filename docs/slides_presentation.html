Phần 1: Kiến Trúc Phần Mềm

6 Mẫu Design Pattern Cốt Lõi Được Áp Dụng

🏭

Factory Method

Khởi tạo các dòng đồ uống (Coffee, Tea, Matcha, Smoothie) đóng gói logic tạo đối tượng tách biệt.

🎀

Decorator Pattern

Tùy biến đồ uống động: Tăng Size L (+10k), thêm Topping trân châu/kem cheese, ghi chú mà không sửa class gốc.

🏷️

Strategy Pattern

Linh hoạt thuật toán khuyến mãi: Giảm 10% thành viên, VIP giảm 15%, BOGO Mua 1 tặng 1 trong lúc thanh toán.

🔌

Adapter Pattern

Tích hợp đa kênh thanh toán (Tiền mặt Cash, VietQR VNPay, MoMo) qua một giao diện IPaymentGateway duy nhất.

🚦

State Pattern

Quản lý vòng đời đơn tại Bếp (Kitchen KDS): Chờ Pha Chế (Pending) ➔ Đang Làm (Preparing) ➔ Sẵn Sàng (Ready).

📢

Observer Pattern

Tự động phát thông báo khi đơn được thanh toán: Bếp nhận đơn pha chế, Quản trị cập nhật doanh thu & trừ tồn kho.

Phần 2: Kiểm Thử Phần Mềm

Tại Sao Sử Dụng Microsoft Playwright E2E?

⚡

Thao Tác Thật Như Người Dùng (Real User Simulation)

Tự động bật trình duyệt Chrome, click chuột, gõ phím tìm kiếm, chọn dropdown và xác thực dữ liệu giao diện.

🎥

Tự Động Quay Video HD Từng Bài Test

Cấu hình video tự động ghi hình toàn bộ màn hình 1280x720, lưu thành file .webm xem ngay trên web hoặc nộp bài.

📊

Báo Cáo Trực Quan (HTML Interactive Report)

Báo cáo chuẩn gồm thời gian thực thi, DOM snapshot, trace log và video được đính kèm trực tiếp.

playwright.config.js HD Recording 
use: {
  baseURL: 'http://localhost:8088',
  video: {
    mode: 'on', // Quay video mọi test
    size: { width: 1280, height: 720 },
  },
  launchOptions: {
    slowMo: 400, // Độ trễ dễ quan sát
  },
}
✅ Đảm bảo tính lặp lại (reproducibility) và loại bỏ hoàn toàn sai sót do thao tác thủ công.
Phần 3: Trọng Tâm Kỹ Thuật

Code Playwright Test Thực Chất Đang Test Những Gì?

1. Định Vị (Locators)

Tìm chính xác thành phần UI trên DOM cây giao diện:

  • • #menuSearch (Ô tìm kiếm)
  • • #discountSelect (Dropdown mã)
  • • #btnOpenCheckout (Nút tính tiền)
  • • button[data-tab-target]
2. Hành Động (Actions)

Mô phỏng hành vi của người thu ngân:

  • • page.click() : Bấm chọn món
  • • page.fill() : Gõ "Bạc xỉu", Note
  • • selectOption() : Đổi mã giảm
  • • waitForTimeout() : Dừng xem QR
3. Khẳng Định (Assertions)

Kiểm tra kết quả Design Pattern có chạy đúng:

  • • expect().toBeVisible()
  • • expect().toBeEnabled()
  • • expect().not.toHaveText('0')
  • • Kiểm tra đơn giá cộng dồn

💡 Mối liên kết giữa Code Test & Design Patterns:

Playwright không chỉ test click nút, mà đang kiểm chứng logic toán học và trạng thái: Decorator có tính cộng tiền Size L (+10k) không? Strategy có trừ chuẩn 10%/15% không? Adapter có sinh mã VietQR theo đúng số tiền tổng không?
